# a0006 サバイバー系アクションゲーム 仕様書

## 0. この仕様書の使い方

- 実装は **フェーズ単位** で進める（§18）。一度に全部投げない。
- 各フェーズの「受け入れ基準」を満たしたら次へ進む。
- 数値（ダメージ、湧き量など）は **すべて暫定**。`src/data/` の JSON を書き換えるだけで調整できる構造にすること。
- §17 の「実装時の落とし穴」は着手前に必ず読むこと。

---

## 1. 概要

ローグライト・サバイバー系のブラウザゲーム。プレイヤーは移動のみを操作し、攻撃は自動。押し寄せる敵を倒して経験値を集め、レベルアップのたびに3択からスキルを選んでビルドを組み、制限時間を生き延びる。

### ゴール
- PC（キーボード）とスマホ（タッチ）の両方で 60fps で遊べる
- 1プレイ15分で完結し、失敗しても「メタ進行」で永続的に強くなる
- 3ステージ + 永続育成まで含んだフル版

### 非ゴール（作らないもの）
- オンライン対戦、ランキング、サーバー通信
- 課金、広告
- アカウント機能（セーブは localStorage のみ）
- ストーリー、カットシーン、ボイス
- ステージごとの地形・障害物（背景は無限スクロールの平面のみ）

## 4. アーキテクチャ

### 4.1 ゲームループ
- **固定タイムステップ 60Hz（16.667ms）** + アキュムレータ方式。
- 1フレームで処理する更新回数は **最大3回** に制限（重い端末でスパイラルしないため）。
- 描画は毎フレーム1回。補間は不要（速度が遅いので目立たない）。

```
accumulator += min(deltaMS, 100)
steps = 0
while accumulator >= FIXED_DT && steps < 3:
    update(FIXED_DT)
    accumulator -= FIXED_DT
    steps++
render()
```

### 4.2 更新順序
1. 入力読み取り
2. プレイヤー移動
3. 敵スポーン
4. 敵AI・移動
5. 武器クールダウン更新・発射
6. 弾の移動
7. 空間ハッシュ再構築
8. 当たり判定（弾↔敵、敵↔プレイヤー、ジェム↔プレイヤー）
9. ダメージ適用・死亡処理
10. 経験値・レベルアップ判定
11. カメラ追従
12. UI更新

### 4.3 エンティティ管理
- **配列 + オブジェクトプール**。毎フレームの `new` は禁止。
- 敵・弾・ジェムは全てプールから取得し、死亡時にプールへ返却する。
- 削除は `splice` ではなく **swap-remove**（末尾と入れ替えて `pop`）。

## 5. 画面遷移

```
Title
 └→ StageSelect ─→ Play ─→ Result ─→ StageSelect
      └→ Upgrade（恒常強化）
```

- `Play` 中のレベルアップは **シーン遷移ではなくポーズ + モーダル**。ゲーム状態は保持したまま更新を止める。
- ブラウザのタブが非アクティブになったら自動ポーズ（`visibilitychange`）。

---

## 6. ワールドとカメラ

- ワールドは無限平面。座標は px 単位の float。
- カメラはプレイヤーを画面中央に固定（デッドゾーンなし、遅延なし）。
- 背景は 256px のタイルテクスチャを `TilingSprite` で無限スクロール。
- **画面外の敵は描画しない**（`visible = false`）。ただし更新は続ける。

### 論理解像度
- 基準を **横 1280 × 縦 720** とし、`resizeTo: window` で実サイズに追従。
- カメラのズームは端末幅で決める：
  - 幅 < 768px（スマホ）: ズーム 0.75（相対的に広く見せる）
  - それ以外: ズーム 1.0
- **画面比が変わっても「見える範囲の広さ」が極端に変わらないこと。** 縦持ちスマホで理不尽にならないよう、縦の可視範囲は最低 640 ワールド px を確保する。

## 7. プレイヤー

| パラメータ | 初期値 |
|---|---|
| 最大HP | 100 |
| 移動速度 | 200 px/s |
| 当たり判定半径 | 12 px |
| ジェム取得範囲 | 60 px |
| 被弾後の無敵時間 | 0.5 s |
| 自動回復 | 0 HP/s |

- 移動は8方向ではなく **アナログ**（正規化ベクトル × 速度）。
- 被弾時は 0.1 秒だけスプライトを白く点滅させ、無敵中は半透明。

### キャラクター（3体）
| ID | 名前 | 初期武器 | 特性 |
|---|---|---|---|
| `runner` | ランナー | ショット | 移動速度 +15%、最大HP -10% |
| `tank` | ヘヴィ | オーブ | 最大HP +30%、移動速度 -10% |
| `sniper` | スナイパー | 手裏剣 | 攻撃力 +15%、取得範囲 -20% |

- `runner` は最初から解放。`tank` はステージ1クリアで解放。`sniper` はコイン 500 で解放。

## 8. 武器（5種）

すべて自動発射。レベル1〜5まで強化でき、Lv5 で進化条件が開く。

| ID | 名前 | 挙動 | Lv1 ダメージ | Lv1 CD | 備考 |
|---|---|---|---|---|---|
| `shot` | ショット | 最も近い敵へ弾を1発 | 10 | 0.8s | Lvで弾数 1→3 |
| `orb` | オーブ | 自機の周囲を回転 | 8/接触 | 常時 | Lvで個数 1→4、半径拡大 |
| `shuriken` | 手裏剣 | 直線に飛び、敵を貫通 | 12 | 1.2s | Lvで貫通数 2→5 |
| `thunder` | 落雷 | ランダムな敵の位置に範囲攻撃 | 25 | 2.5s | Lvで落雷数 1→4 |
| `flame` | 火炎 | 前方扇形に持続ダメージ | 5/0.2s | 常時 | Lvで角度と射程拡大 |

### レベルごとの伸び（共通ルール）
- Lv2: ダメージ +30%
- Lv3: 弾数 or 個数 +1
- Lv4: ダメージ +30%、CD -15%
- Lv5: 弾数 or 個数 +1、CD -15%

具体値は `weapons.json` に **レベルごとの完全な数値テーブル**として持たせる（計算式ではなくベタ書き。バランス調整しやすいため）。

## 9. パッシブ（5種）

| ID | 名前 | 効果（1レベルあたり） | 最大Lv |
|---|---|---|---|
| `power` | パワー | 全武器ダメージ +10% | 5 |
| `haste` | ヘイスト | 全武器CD -8% | 5 |
| `boots` | ブーツ | 移動速度 +8% | 5 |
| `magnet` | マグネット | ジェム取得範囲 +25% | 5 |
| `vitality` | バイタリティ | 最大HP +15%、HP自動回復 +0.3/s | 5 |

CD短縮は **合計 -50% を下限としてクランプ**すること。

## 10. 進化

**武器 Lv5 + 指定パッシブ Lv3** の両方を満たすと、レベルアップ時の3択に進化選択肢が出る（通常より優先度高く出す）。進化すると元の武器は置き換わる。

| 元武器 | 必要パッシブ | 進化後 | 効果 |
|---|---|---|---|
| `shot` | `haste` | ガトリング | 連射化、CD 0.15s、ダメージ 18 |
| `orb` | `boots` | サテライト | 個数6、二重回転、ダメージ 25 |
| `shuriken` | `power` | ブーメラン | 貫通無制限、戻ってくる、ダメージ 40 |
| `thunder` | `power` | ストーム | 画面全体に連続落雷、ダメージ 45 |
| `flame` | `vitality` | インフェルノ | 全方位持続、与ダメージの5%をHP吸収 |

## 11. 敵

| ID | 名前 | HP | 速度 | 接触ダメージ | 半径 | ドロップ |
|---|---|---|---|---|---|---|
| `walker` | 歩行者 | 20 | 60 | 8 | 12 | ジェム(小) |
| `runner_z` | 走者 | 12 | 130 | 6 | 10 | ジェム(小) |
| `tank_z` | 重装 | 120 | 40 | 18 | 20 | ジェム(中) |
| `spitter` | 遠距離 | 30 | 50 | 弾12 | 12 | ジェム(中) |
| `boss` | ボス | 3000 | 55 | 30 | 48 | ジェム(大)×10 + 確定クリア |

- AI は **全種プレイヤーへの直線追尾**。`spitter` のみ距離 250px を保って弾を撃つ。
- 敵同士は重ならないよう **軽い押し出し**（半径が重なったら互いに離す。1フレームあたり最大2px、空間ハッシュの同一セル内のみで判定）。
- 敵の HP と接触ダメージは、経過時間に応じた **難易度倍率** を掛ける（§12）。

## 12. ステージとスポーン

1ステージ = **15分（900秒）**。14:00 時点でボスが出現し、倒すとクリア。

### スポーン仕様
- 画面外（カメラ矩形の外周 + 80px）のランダムな位置に湧く。
- 30秒ごとに「ウェーブ」が切り替わり、湧く種類と1秒あたりの湧き数が変わる。
- 難易度倍率：敵HP `1.0 + 経過分数 × 0.18`、接触ダメージ `1.0 + 経過分数 × 0.06`。

### 湧きテーブル（ステージ1・抜粋。残りは同じ形式で `stages.json` に定義）
| 時間 | 湧き/秒 | 内訳 |
|---|---|---|
| 0:00–2:00 | 2 | walker 100% |
| 2:00–5:00 | 4 | walker 70% / runner_z 30% |
| 5:00–8:00 | 6 | walker 50% / runner_z 30% / tank_z 20% |
| 8:00–11:00 | 8 | walker 40% / runner_z 30% / tank_z 20% / spitter 10% |
| 11:00–14:00 | 11 | walker 30% / runner_z 30% / tank_z 25% / spitter 15% |
| 14:00 | ボス | boss ×1（以降 通常湧きは 4/秒に減衰） |

### 3ステージの差分
| ステージ | 解放条件 | 難易度倍率 | 背景 | 特徴 |
|---|---|---|---|---|
| 1. 市街地 | 最初から | ×1.0 | アスファルト | 標準 |
| 2. 廃工場 | ステージ1クリア | ×1.4 | 鉄板 | `tank_z` の比率が高い |
| 3. 汚染区 | ステージ2クリア | ×1.9 | 汚泥 | `spitter` が多く、湧き数 +30% |

## 13. 経験値・レベルアップ・ピックアップ

- ジェム（小=1 / 中=5 / 大=20 EXP）。プレイヤーの取得範囲に入ると加速しながら吸い寄せられる。
- レベルアップ必要EXP：`10 + (level - 1) * 8 + floor(level / 5) * 20`
- レベルアップでゲームをポーズし、**3つの選択肢** を提示：
  - 未取得の武器（所持上限6）、既存武器の強化、パッシブ、進化（条件を満たしていれば優先）
  - 選択肢が3つ揃わない場合は「小回復（HP 20%）」で埋める
  - **リロール**：1プレイにつき3回まで選択肢を引き直せる
- その他のドロップ（敵から低確率）：
  - 回復（HP 30%）／マグネット（画面内のジェム全取得）／爆弾（画面内の敵に 200 ダメージ）

## 14. メタ進行（永続育成）

- 1プレイ終了時に **コイン** を獲得：`floor(倒した敵数 / 5) + 生存分数 × 10`（クリア時は ×1.5）。
- `UpgradeScene` でコインを使って恒常強化を購入。

| ID | 効果 | 最大Lv | コスト（Lv nで `base * n`） |
|---|---|---|---|
| `meta_hp` | 最大HP +5% | 10 | 50 |
| `meta_power` | ダメージ +4% | 10 | 60 |
| `meta_speed` | 移動速度 +3% | 5 | 70 |
| `meta_regen` | HP自動回復 +0.2/s | 5 | 80 |
| `meta_start` | 開始レベル +1 | 3 | 200 |
| `meta_reroll` | リロール回数 +1 | 3 | 150 |

### セーブデータ（localStorage キー: `a0006_save_v1`）
```json
{
  "version": 1,
  "coins": 0,
  "unlockedCharacters": ["runner"],
  "clearedStages": [],
  "metaUpgrades": { "meta_hp": 0, "meta_power": 0 },
  "stats": { "totalKills": 0, "totalPlaytimeSec": 0, "bestTimeSec": 0 }
}
```
- 読み込み時に `version` を検証し、不一致・破損時は **初期値にフォールバック**（クラッシュさせない）。

## 15. 当たり判定とパフォーマンス

### 空間ハッシュ
- セルサイズ **64px**。`Map<number, Entity[]>` でキーは `(cellX * 73856093) ^ (cellY * 19349663)`。
- 毎フレーム先頭でクリアして再構築（配列は使い回し、`new` しない）。
- 判定は円 vs 円のみ。距離は **平方根を取らず二乗で比較**。

### 判定の組み合わせ
| 対象 | 方法 |
|---|---|
| 弾 → 敵 | 空間ハッシュ（弾の位置の周辺9セル） |
| 敵 → プレイヤー | 空間ハッシュ（プレイヤー周辺9セル） |
| ジェム → プレイヤー | 空間ハッシュ（取得範囲をカバーするセル） |
| 敵 → 敵（押し出し） | 同一セル内のみ |

### 性能要件
| 項目 | 目標 |
|---|---|
| フレームレート | 60fps（iPhone SE 世代相当のスマホで 55fps 以上） |
| 敵の同時存在上限 | スマホ 400 / PC 800（超過分はスポーンをスキップ） |
| 弾の同時存在上限 | 600 |
| ジェムの同時存在上限 | 400（超えたら最も古いものを自動回収） |
| 初回ロード | 3秒以内（バンドル gzip 500KB 以内） |

### 描画の最適化
- **スプライトは1枚のテクスチャアトラスにまとめる**（バッチングを効かせるため）。アトラスは `assets/atlas.png` + `atlas.json`。
- 画面外エンティティは `visible = false`。
- テキストは毎フレーム更新しない（HUDの数値は値が変わった時のみ `text` を代入）。
- `Graphics` の毎フレーム再構築は禁止。

## 16. UI とアートディレクション

Claude Code が汎用テンプレ的な見た目を作らないよう、以下を明示的に指定する。

### コンセプト
「深夜の非常灯」。暗い画面に、**琥珀色の警告灯**だけが情報を照らしている。装飾は足さず、視認性で殴る。

### カラートークン（`ui/theme.ts` に定義し、これ以外の色を使わない）
```ts
export const COLORS = {
  bgDeep:    0x0d0f14,  // 背景の最暗部
  bgSurface: 0x1a1e26,  // パネル・モーダル背景
  line:      0x2f3742,  // 罫線・枠
  textMain:  0xe8e6e1,  // 主要テキスト
  textDim:   0x7d8595,  // 補助テキスト
  amber:     0xffb02e,  // アクセント（EXP、レア、警告灯）
  hpRed:     0xd94141,  // HP
  toxic:     0x6ee085,  // 回復・良い変化
} as const;
```

### タイポグラフィ
- 数値・タイマー・ダメージ表示：**等幅フォント**（`ui-monospace, "SF Mono", "Roboto Mono", monospace`）。桁が揺れないこと。
- 見出し・スキル名：太字サンセリフ、**字間 +0.08em、大文字/カタカナは全角揃え**。
- 本文は使わない。UIテキストは全て短いラベルのみ。

### HUD 配置
```
┌────────────────────────────────┐
│ [HPバー========      ]   12:34  │  上部：HP（左）、残り時間（中央・等幅）
│ [EXPバー=====================]  │  HPのすぐ下に細いEXPバー（琥珀）
│                          Lv.12  │  右上：レベル
│                                 │
│              (ゲーム画面)        │
│                                 │
│  ◎                     💰 240   │  左下：バーチャルスティック（スマホのみ）
└────────────────────────────────┘  右下：獲得コイン
```

- HPバーは **減少時に一瞬だけ白い残像** を残してから追いつく（被弾量が見えるように）。
- 残り時間は 1:00 を切ったら琥珀色で点滅。

### レベルアップモーダル
- 背景を暗くして 3枚のカードを横並び（スマホは縦並び）。
- カードには **アイコン / 名前 / 現在Lv→次Lv / 効果の1行説明** のみ。説明文は「ダメージ +30%」のように**数値を必ず含める**。
- 進化カードは枠を琥珀色にして、他と明確に差別化する。
- リロールボタンは残り回数を数字で表示（`リロール ×2`）。

### 演出（やりすぎない）
- ダメージ数値は表示しない（大量の敵で画面が埋まるため）。代わりに **敵の被弾時に2フレーム白フラッシュ**。
- 敵の死亡時は小さなパーティクル4個のみ。プールから取る。
- 画面シェイクはボス出現時と爆弾使用時のみ。

## 17. 入力

### PC
- WASD / 矢印キー（同時押しで斜め移動）
- `ESC` でポーズ
- レベルアップ選択は `1` `2` `3` キー、`R` でリロール

### スマホ
- **バーチャルスティック**：画面左半分の任意の場所をタッチした位置に出現。ドラッグで方向入力。離すと消える（固定位置ではない）。
- スティックのデッドゾーン 12px、最大入力距離 60px。
- `touch-action: none` と `user-select: none` を設定し、スクロール・ダブルタップズームを無効化。

### 両対応
- 入力レイヤーは `InputState { moveX: number, moveY: number }` に正規化して抽象化する。ゲームロジックは入力方式を知らない。
- ポインタ種別で自動判定し、**タッチ入力を検出したらスティックを有効化**（UA判定はしない）。

## 18. 実装時の落とし穴（PixiJS v8）

**v7 以前の書き方と混同しないこと。以下は v8 の正しい書き方。**

1. **初期化は非同期**
```ts
import { Application } from 'pixi.js';

const app = new Application();
await app.init({
  resizeTo: window,
  background: COLORS.bgDeep,
  antialias: false,
  resolution: Math.min(window.devicePixelRatio, 2),
  autoDensity: true,
});
document.body.appendChild(app.canvas);  // ← app.view ではない
```

2. **`app.canvas` を使う。`app.view` は v8 で非推奨。**

3. **ticker のコールバック引数は `Ticker` インスタンス**（v7 は deltaTime の数値だった）
```ts
app.ticker.add((ticker) => {
  const deltaMS = ticker.deltaMS;  // ← 引数を数値として扱わない
});
```

4. **アセット読み込みは `Assets`**
```ts
import { Assets } from 'pixi.js';
const atlas = await Assets.load('/assets/atlas.json');
```

5. **`ParticleContainer` は v8 で仕様が変わっており、v7 の使い方は通らない。** 本プロジェクトでは使わず、通常の `Container` に同一アトラスのスプライトを入れてバッチングを効かせる。

6. **`Graphics` の API が変更されている**（`beginFill`/`endFill` → `fill()`）。そもそも毎フレーム再構築しないこと。

7. TypeScript の `strict` を有効にすること。`any` の使用は禁止。
