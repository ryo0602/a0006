# a0006 サバイバー系アクションゲーム 仕様書

## 0. この仕様書の使い方

- 実装は **フェーズ単位** で進める（§18）。一度に全部投げない。
- 各フェーズの「受け入れ基準」を満たしたら次へ進む。
- 数値（ダメージ、湧き量など）は **すべて暫定**。`src/data/` の JSON を書き換えるだけで調整できる構造にすること。
- §17 の「実装時の落とし穴」は着手前に必ず読むこと。

---

## 1. 概要

ローグライト・サバイバー系のブラウザゲーム。プレイヤーは移動のみを操作し、攻撃は自動。押し寄せる敵を倒して経験値を集め、レベルアップのたびに3択からスキルを選んでビルドを組み、制限時間を生き延びる。

### ゴール
- PC（キーボード）とスマホ（タッチ）の両方で 60fps で遊べる
- 1プレイ5分で完結し、失敗しても「メタ進行」で永続的に強くなる（Phase 7 で15分から短縮）
- 3ステージ + 永続育成まで含んだフル版

### 非ゴール（作らないもの）
- オンライン対戦、ランキング、サーバー通信
- 課金、広告
- アカウント機能（セーブは localStorage のみ）
- ストーリー、カットシーン、ボイス
- ステージごとの地形・障害物（背景は無限スクロールの平面のみ）

## 4. アーキテクチャ

### 4.1 ゲームループ
- **固定タイムステップ 60Hz（16.667ms）** + アキュムレータ方式。
- 1フレームで処理する更新回数は **最大3回** に制限（重い端末でスパイラルしないため）。
- 描画は毎フレーム1回。補間は不要（速度が遅いので目立たない）。

```
accumulator += min(deltaMS, 50)
steps = 0
while accumulator >= FIXED_DT && steps < 3:
    update(FIXED_DT)
    accumulator -= FIXED_DT
    steps++
if steps == 3:
    accumulator %= FIXED_DT   // 3ステップの上限に達した場合、残余は切り捨てる（遅延を蓄積させない）
render()
```

### 4.2 更新順序
1. 入力読み取り
2. プレイヤー移動
3. 敵スポーン
4. 敵AI・移動
5. 空間ハッシュ再構築（武器の索敵が同一フレームの敵位置を見られるよう、発射より前に行う）
6. 武器クールダウン更新・発射
7. 弾の移動
8. 敵弾の移動
9. 当たり判定（弾↔敵、敵↔プレイヤー、敵弾↔プレイヤー、ジェム↔プレイヤー）
10. ダメージ適用・死亡処理
11. 経験値・レベルアップ判定
12. カメラ追従
13. UI更新

### 4.3 エンティティ管理
- **配列 + オブジェクトプール**。毎フレームの `new` は禁止。
- 敵・弾・ジェムは全てプールから取得し、死亡時にプールへ返却する。
- 削除は `splice` ではなく **swap-remove**（末尾と入れ替えて `pop`）。

## 6. ワールドとカメラ

- ワールドは無限平面。座標は px 単位の float。
- カメラはプレイヤーを画面中央に固定（デッドゾーンなし、遅延なし）。
- 背景は 256px のタイルテクスチャを `TilingSprite` で無限スクロール。
- **画面外の敵は描画しない**（`visible = false`）。ただし更新は続ける。

### 論理解像度
- **1280 × 720 はバランス設計上の想定可視範囲であり、実行時の解像度ではない。** 実サイズは `resizeTo: window` で追従する。
- カメラのズームは以下で決める：
  ```
  base = 画面幅 < 768 ? 0.75 : 1.0
  zoom = clamp(min(base, 画面高 / 640), 0.45, 1.0)
  ```
- **画面比が変わっても「見える範囲の広さ」が極端に変わらないこと。** 上式により、縦の可視範囲は（下限 0.45 にかからない限り）最低 640 ワールド px を確保する。

## 7. プレイヤー

| パラメータ | 初期値 |
|---|---|
| 最大HP | 100 |
| 移動速度 | 200 px/s |
| 当たり判定半径 | 12 px |
| ジェム取得範囲 | 60 px |
| 被弾後の無敵時間 | 0.5 s |
| 自動回復 | 0 HP/s |

- 上記のパラメータはコードに埋め込まず、**`src/data/player.json` に持たせる**。

- 移動は8方向ではなく **アナログ**（正規化ベクトル × 速度）。
- 被弾時は 0.1 秒だけスプライトの不透明を維持し、残りの無敵時間は半透明にする（被弾の瞬間と無敵中を見分けさせる。tint は乗算合成で白くできないため「白点滅」は採用しない。Phase 6 で合意）。

|---|---|---|---|---|

| `tank` | ヘヴィ | オーブ | 最大HP +30%、移動速度 -10% | ステージ1クリア |
| `sniper` | スナイパー | 手裏剣 | 攻撃力 +15%、取得範囲 -20% | コイン 500 |

## 8. 武器（9種）

すべて自動発射。レベル1〜5まで強化でき、Lv5 で進化条件が開く。

| ID | 名前 | 挙動 | Lv1 ダメージ | Lv1 CD | 備考 |
|---|---|---|---|---|---|
| `shot` | ショット | 最も近い敵へ弾を1発 | 14 | 0.65s | Lvで弾数 1→3 |
| `orb` | オーブ | 自機の周囲を回転 | 8/接触 | 常時 | Lvで個数 1→4、半径拡大 |
| `shuriken` | 手裏剣 | 直線に飛び、敵を貫通 | 12 | 1.2s | Lvで貫通数 2→5 |
| `thunder` | 落雷 | ランダムな敵の位置に範囲攻撃 | 25 | 2.5s | Lvで落雷数 1→4 |
| `flame` | 火炎 | 前方扇形に持続ダメージ | 5/0.2s | 常時 | Lvで角度と射程拡大 |
| `spear` | スピア | **向いている方向**へ高貫通の刺突（索敵しない） | 16 | 1.1s | Phase 8。Lvで弾数 1→3・貫通 4→6 |
| `axe` | 投斧 | 斜め上へ投げ重力で放物線を描く | 30 | 1.6s | Phase 8。Lvで弾数 1→3 |
| `mine` | 地雷 | 足元へ設置し、敵の接触で範囲爆発 | 45 | 2.2s | Phase 8 設置型。「弾数」= 同時設置数 2→4 |
| `drone` | ドローン | 浮遊する子機が最寄りの敵へ自動射撃 | 10 | 0.8s | Phase 8 召喚型。武器枠に数える。「弾数」= 1射撃の弾数 1→3 |

### 解放（Phase 8）
`spear` / `axe` は**ステージ2クリア**、`mine` / `drone` は**ステージ3クリア**で解放される
（`weapons.json` の `unlockStage`）。未解放の武器はレベルアップ候補に出ない。
候補プールの肥大を抑え、初見が既存5種で基本を学べるようにするための段階解放。

### レベルごとの伸び（共通ルール）
- Lv2: ダメージ +30%
- Lv3: 弾数 or 個数 +1
- Lv4: ダメージ +30%、CD -15%
- Lv5: 弾数 or 個数 +1、CD -15%

「弾数」が何を指すかは武器ごとに定義する（上表の備考。地雷は同時設置数、ドローンは1射撃の弾数）。
具体値は `weapons.json` に **レベルごとの完全な数値テーブル**として持たせる（計算式ではなくベタ書き。バランス調整しやすいため）。

## 10. 進化

**武器 Lv5 + 指定パッシブ Lv3** の両方を満たすと、レベルアップ時の3択に進化選択肢が出る（通常より優先度高く出す）。進化すると元の武器は置き換わる。

### 進化リーチ補正（Phase 7）
- 「武器 Lv5（未進化）かつ 指定パッシブ Lv2 以上」の状態を**進化リーチ**と定義する。
- リーチ中は、その進化に必要なパッシブの**抽選重みを `evolutionReachWeight` 倍**（`leveling.json`、既定 3）にする。
- リーチが複数ある場合はすべてに適用する（同一パッシブに複数のリーチが重なる場合は重ね掛け）。
- 狙い: 正しく育てたのに最後の1ピックが抽選運で引けない事故を減らす。リロールの価値とも噛み合う。

| 元武器 | 必要パッシブ | 進化後 | 効果 |
|---|---|---|---|
| `shot` | `haste` | ガトリング | 連射化、CD 0.15s、ダメージ 18 |
| `orb` | `boots` | サテライト | 個数6、二重回転、ダメージ 25 |
| `shuriken` | `power` | ブーメラン | 貫通無制限、戻ってくる、ダメージ 40 |
| `thunder` | `power` | ストーム | 画面全体に連続落雷、ダメージ 45 |
| `flame` | `vitality` | インフェルノ | 全方位持続、与ダメージの5%をHP吸収 |
| `spear` | `crit` | ランス | 貫通無制限、飛びながら加速、ダメージ 45（Phase 8） |
| `axe` | `area` | メテオ | 隕石2連、着弾で範囲爆発 60（Phase 8） |
| `mine` | `area` | クラスターマイン | 爆発 60 + 子爆発 30×3 を散布（Phase 8） |
| `drone` | `shield` | ツインドローン | 2機化、CD 0.4s、ダメージ 20（Phase 8） |

## 11. 敵

| ID | 名前 | HP | 速度 | 接触ダメージ | 半径 | ドロップ |
|---|---|---|---|---|---|---|
| `walker` | 歩行者 | 16 | 60 | 8 | 12 | ジェム(小) |
| `runner_z` | 走者 | 12 | 130 | 6 | 10 | ジェム(小) |
| `tank_z` | 重装 | 120 | 40 | 18 | 20 | ジェム(中) |
| `spitter` | 遠距離 | 30 | 50 | 弾12 | 12 | ジェム(中) |
| `boss` | ボス | 2600 | 55 | 30 | 48 | ジェム(大)×10 + 確定クリア |

- AI は **全種プレイヤーへの直線追尾**。`spitter` のみ距離 250px を保って弾を撃つ。
- 敵同士は重ならないよう **軽い押し出し**（半径が重なったら互いに離す。1フレームあたり最大2px、空間ハッシュの同一セル内のみで判定）。
- 敵の HP と接触ダメージは、経過時間に応じた **難易度倍率** を掛ける（§12）。
- **ボスには §12 の時間係数を適用しない。ステージ係数 × 危険度係数を適用する**（Phase 9 で危険度係数を追加。高難易度でボス戦だけ据え置きにならないようにする）。
- **ボスは押し出しの影響を受けない**（押される側にならない）。周囲の敵は通常どおりボスに押し出される。

## 12. ステージとスポーン

1ステージ = **5分（300秒）**。4:30 時点でボスが出現し、倒すとクリア。
**ボス出現後はステージタイマーを停止し、ボスを倒すまで継続する。5分経過による失敗はない。**
（Phase 7 で15分から短縮。テストプレイで1周が長すぎるという評価だったため）

### スポーン仕様
- 画面外（カメラ矩形の外周 + 80px）のランダムな位置に湧く。
- 「ウェーブ」はテーブルの時間区切り（40〜70秒）で切り替わり、湧く種類と1秒あたりの湧き数が変わる。
- 敵の強さは **時間係数 × ステージ係数 × 危険度係数** の3層で決まる（Phase 9 で用語整理）：
  - **時間係数**：敵HP `1.0 + 経過分数 × 0.22`（終端 ×1.99）、接触ダメージ `1.0 + 経過分数 × 0.08`（終端 ×1.36）。
    終端倍率が旧15分仕様（×3.52 / ×1.84）より低いのは意図的。当初案（0.36 / 0.11）は
    自動プレイ実測でキル能力に対する敵側の伸びが速すぎたため下方修正した。
  - **ステージ係数**：`stages.json` の `difficultyMul`（1.0 / 1.4 / 1.9）。
  - **危険度係数**：下記「危険度」。危険度0 = 1.0 で、Phase 7/8 のバランスがそのまま基準になる。

### 危険度（周回難易度。Phase 9）
- 全体で1軸の **危険度 Lv0〜5**。ステージ選択画面のセレクタ（◀▶ / ←→キー）で選ぶ。
- 危険度 n は「危険度 n-1 でいずれかのステージをクリア」で解放。選択値はセーブに保持。
- 危険度 n の効果（係数は `stages.json` の `danger` テーブル）：
  - 敵HP ×(1 + 0.25n)、接触/弾ダメージ ×(1 + 0.15n)（ボスにも適用。§11）
  - **エリート敵（tank_z / spitter）の抽選重み ×(1 + 0.15n)**。湧きレートは上げない
    （レートを上げると敵上限に張り付いて係数が無効化されるため、数ではなく質で上げる。
    登場する敵種は変えないのでステージ個性は保たれる）
  - コイン ×(1 + 0.35n)（§14）。HP係数より高く設定し、クリアできる限り高難易度が常に時間効率で得になる

### 湧きテーブル（ステージ1・抜粋。残りは同じ形式で `stages.json` に定義）
| 時間 | 湧き/秒 | 内訳 |
|---|---|---|
| 0:00–0:40 | 2 | walker 100% |
| 0:40–1:30 | 3.5 | walker 70% / runner_z 30% |
| 1:30–2:20 | 5 | walker 50% / runner_z 30% / tank_z 20% |
| 2:20–3:30 | 6.5 | walker 40% / runner_z 30% / tank_z 20% / spitter 10% |
| 3:30–4:30 | 8 | walker 30% / runner_z 30% / tank_z 25% / spitter 15% |
| 4:30 | ボス | boss ×1。**出現時に通常敵は全消滅**（ドロップなし）し、以降の通常湧きは 1.5/秒（stage3 は 2/秒） |

ボス出現時の全消滅（ボスアリーナ）は Phase 7 の実測で導入した仕様。5分設計ではボス出現時点の
残存敵が数百体規模になり、「最寄りの敵を狙う」武器がボスに一切当たらないことが確認されたため、
ボス戦を1対1主体に切り替える。

### 3ステージの差分
| ステージ | 解放条件 | 難易度倍率 | 背景 | 特徴 |
|---|---|---|---|---|
| 1. 市街地 | 最初から | ×1.0 | アスファルト | 標準 |
| 2. 廃工場 | ステージ1クリア | ×1.4 | 鉄板 | `tank_z` の比率が高い |
| 3. 汚染区 | ステージ2クリア | ×1.9 | 汚泥 | `spitter` が多く、湧き数 +30% |

## 13. 経験値・レベルアップ・ピックアップ

- ジェム（小=2 / 中=7 / 大=30 EXP）。プレイヤーの取得範囲に入ると加速しながら吸い寄せられる。
- レベルアップ必要EXP：`25 + (level - 1) * 20`（`leveling.json` の expBase / expPerLevel。expStepEvery5 は 0）
  - 5分周の実測水準: メタなしで Lv13〜16、フル成長メタ + 集中プレイで進化到達が現実的。
  - レベルアップ間隔がプレイ中を通してほぼ均一（約20秒）になるよう、実測のEXP収入カーブに傾きを合わせている。
- レベルアップでゲームをポーズし、**3つの選択肢** を提示：
  - 未取得の武器（所持上限6・解放済みのみ）、既存武器の強化、パッシブ、進化（条件を満たしていれば優先）
  - 選択肢が3つ揃わない場合は「小回復（HP 20%）」で埋める
  - **リロール**：1プレイにつき3回まで選択肢を引き直せる
- 候補の抽選重み（Phase 8。係数は `leveling.json`）：
  - **保証枠**: 所持武器に Lv5 未満があれば、3枠の1つは必ず所持武器の強化（対象武器は等確率）。
    伸ばしかけの武器が候補プールの肥大で最後まで伸ばせない事故を防ぐ
  - 所持武器の強化: 重み 1.3（`weaponUpWeight`）
  - 未所持武器: 所持数 3 個で 0.7 / 4 個で 0.4 / 5 個で 0.2（`newWeaponWeightByOwned`）
  - 進化リーチ中のパッシブ: ×3（§10 の `evolutionReachWeight`）
- その他のドロップ（敵から低確率）：
  - 回復（HP 30%）／マグネット（画面内のジェム全取得）／爆弾（画面内の敵に 200 ダメージ）

## 14. メタ進行（永続育成）

- 1プレイ終了時に **コイン** を獲得：`floor((floor(倒した敵数 / 5) + 生存分数 × 30) × ステージ係数 × 危険度係数)`（クリア時はさらに ×1.5。危険度係数は §12）。
  5分化（Phase 7）で生存分数×10 → ×30、キル数/20 → /5 に変更（時間収入 4.5分×30=135 ≒ 旧14分×10=140 の等価。キル除数は実測キル数 700〜800/周 に合わせて設定し、ステージ1クリアで 400〜450 コイン）。
- ステージ係数は **コイン専用の値**（stage1 = 1.0 / stage2 = 1.6 / stage3 = 2.4。`stages.json` の `coinMultiplier`）。§12 の難易度倍率は流用しない。難しいステージは敵HPが上がるぶんキル数が減り、難易度倍率では相殺されて周回効率がステージ1に劣りかねないため、係数は別途高めに設定する。
- `UpgradeScene` でコインを使って恒常強化を購入。

| ID | 効果 | 最大Lv | コスト（Lv nで `base * n`） |
|---|---|---|---|
| `meta_hp` | 最大HP +5% | 10 | 50 |
| `meta_power` | ダメージ +4% | 10 | 60 |
| `meta_speed` | 移動速度 +3% | 5 | 70 |
| `meta_regen` | HP自動回復 +0.2/s | 5 | 80 |
| `meta_start` | 開始レベル +1 | 3 | 200 |
| `meta_reroll` | リロール回数 +1 | 3 | 150 |
| `meta_exp` | EXP獲得 +10%（成長加速） | 5 | 100 |
| `meta_magnet` | ジェム取得範囲 +10%（回収範囲） | 5 | 60 |

`meta_exp` / `meta_magnet` は Phase 7 で追加した「成長速度」系の枠。進化を1周で狙わず、
メタ進行を積むほど届きやすくする設計の中核（`meta_exp` + `meta_start` + `meta_reroll` = 3,600 コインが進化狙いの優先購入ライン）。

### セーブデータ（localStorage キー: `a0006_save_v1`）
```json

  "coins": 0,
  "unlockedCharacters": ["runner"],
  "clearedStages": [],
  "metaUpgrades": { "meta_hp": 0, "meta_power": 0 },
  "stats": { "totalKills": 0, "totalPlaytimeSec": 0, "bestTimeSec": 0,
             "totalClears": 0, "totalRuns": 0, "killsElite": 0, "crits": 0,

```
- `dangerUnlocked` / `lastDanger` は Phase 9、`achievements` 以下と stats の拡張は Phase 10 追加。
- **`bestTimeSec` は形骸化**（5分固定+タイマー停止でクリア時は常に270）。互換のため残置するが
  表示には使わず、代わりに `bestBossKillSec`（最短ボス討伐秒）を記録・表示する（Phase 10）。

### 実績（Phase 10）
- 定義は `src/data/achievements.json`（30個）。各実績は「事実名（fact）と閾値」の宣言で、

### チャレンジ（Phase 10）

- ステージ3クリアで5本同時解放。**チャレンジ中の危険度は0固定**。メタ強化は有効

- 通常のコイン獲得式はそのまま機能し、初回クリアで追加報酬 300。
- チャレンジのクリアは**進行に影響しない**（clearedStages・危険度解放・キャラ別クリア記録は
  通常プレイのみ）。累計 stats と進化図鑑には算入する。

| ID | 名前 | 対象 | 修飾子 |
|---|---|---|---|
| `rush` | ラッシュ | ステージ1 | walker 100% / 湧き×2 |
| `heavy_march` | 重装行進 | ステージ2 | tank_z 70% / 湧き×0.6 |
| `sniper_nest` | 狙撃手の巣 | ステージ3 | spitter 40% |
| `glass` | ガラスの体 | ステージ1 | HP1 / 敵HP×0.5 |
| `solo` | 一本槍 | ステージ2 | 武器の追加取得禁止 |
- 読み込み時に `version` を検証し、不一致・破損時は **初期値にフォールバック**（クラッシュさせない）。
- **ステージ解放状態の保存は Phase 5 のスコープ。** Phase 4 ではメモリ上でのみ管理し、リロードで初期化されてよい。

## 15. 当たり判定とパフォーマンス

### 空間ハッシュ
- セルサイズ **64px**。`Map<number, Entity[]>` でキーは `(cellX * 73856093) ^ (cellY * 19349663)`。
- 毎フレーム先頭でクリアして再構築（配列は使い回し、`new` しない）。
- 判定は円 vs 円のみ。距離は **平方根を取らず二乗で比較**。

### 判定の組み合わせ
| 対象 | 方法 |
|---|---|
| 弾 → 敵 | 空間ハッシュ（弾の位置の周辺9セル） |
| 敵 → プレイヤー | 空間ハッシュ（プレイヤー周辺9セル） |
| ジェム → プレイヤー | 空間ハッシュ（取得範囲をカバーするセル） |
| 敵 → 敵（押し出し） | 同一セル内のみ |

### 性能要件
| 項目 | 目標 |
|---|---|
| フレームレート | 60fps（iPhone SE 世代相当のスマホで 55fps 以上） |
| 敵の同時存在上限 | スマホ 400 / PC 800（超過分はスポーンをスキップ） |
| 弾の同時存在上限 | 600 |
| ジェムの同時存在上限 | 400（超えたら最も古いものを自動回収） |
| 初回ロード | 3秒以内（バンドル gzip 500KB 以内） |

### 描画の最適化
- **スプライトは1枚のテクスチャアトラスにまとめる**（バッチングを効かせるため）。アトラスは `assets/atlas.png` + `atlas.json`。
- 画面外エンティティは `visible = false`。
- テキストは毎フレーム更新しない（HUDの数値は値が変わった時のみ `text` を代入）。
- `Graphics` の毎フレーム再構築は禁止。

- 画面シェイクはボス出現時と爆弾使用時のみ。

## 18. 実装時の落とし穴（PixiJS v8）

**v7 以前の書き方と混同しないこと。以下は v8 の正しい書き方。**

1. **初期化は非同期**
```ts
import { Application } from 'pixi.js';

const app = new Application();
await app.init({
  resizeTo: window,
  background: COLORS.bgDeep,
  antialias: false,
  resolution: Math.min(window.devicePixelRatio, 2),
  autoDensity: true,
});
document.body.appendChild(app.canvas);  // ← app.view ではない
```

2. **`app.canvas` を使う。`app.view` は v8 で非推奨。**

3. **ticker のコールバック引数は `Ticker` インスタンス**（v7 は deltaTime の数値だった）
```ts
app.ticker.add((ticker) => {
  const deltaMS = ticker.deltaMS;  // ← 引数を数値として扱わない
});
```

4. **アセット読み込みは `Assets`**
```ts
import { Assets } from 'pixi.js';
const atlas = await Assets.load('/assets/atlas.json');
```

5. **`ParticleContainer` は v8 で仕様が変わっており、v7 の使い方は通らない。** 本プロジェクトでは使わず、通常の `Container` に同一アトラスのスプライトを入れてバッチングを効かせる。

6. **`Graphics` の API が変更されている**（`beginFill`/`endFill` → `fill()`）。そもそも毎フレーム再構築しないこと。

7. TypeScript の `strict` を有効にすること。`any` の使用は禁止。

## 拡張フェーズ（Phase 7〜10）

テストプレイのフィードバック（1周15分は長すぎる）を受けた再設計と、その後の拡張。
各フェーズの詳細仕様は着手時に該当章へ反映する。**Phase 7 以降も「1回の指示で1フェーズ」の原則は変わらない。**

### Phase 7: 1周5分化と全数値の再調整
1周 = 5分（300秒）、ボスは 4:30 に出現（以降タイマー停止）。§11〜§14 の全バランス数値を
5分前提で再計算する（湧きテーブル、難易度倍率、必要EXP式、コイン計算、ボスHP）。
進化は**1周では届かず、メタ進行を積むほど届きやすくなる**設計に変える。そのための
「成長速度」系メタ強化（EXP獲得量アップなど）を追加する。コード構造は変えず、
数値・テーブル・メタ強化枠の追加が中心。

**受け入れ基準**
- [ ] 1周が5分で完結し、4:30 にボスが出現する
- [ ] メタ強化なしの初回プレイでは進化に到達できない
